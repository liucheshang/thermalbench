# 常见问题 FAQ

## 1. 为什么要管理员权限？
温度/功耗走 LibreHardwareMonitor 的内核驱动读取，Windows 不给普通进程开这个口子。
非管理员会直接拒绝运行——不装懂、不输出没意义的数据。

## 2. 为什么读不到风扇转速（RPM）？
多数家用本（尤其联想消费线）的 BIOS 根本不向系统上报风扇设备（无 ACPI `PNP0C0B`），
所以任何软件都读不到——这不是 ThermalBench 的缺陷。
工具会自动分两条路：
- **你的机器能读到转速**（CSV 里有转速列）→ 直接用实测转速，画出转速曲线与「转速-温度关系」；
- **读不到** → 用「恒载锯齿」从温度形态反推风扇启停（起转/停转温度、周期、散热增益）。

## 3. 「恒载锯齿」可靠吗？什么情况下会失效？
只在温度落入风扇启停区间（本机约 75~85℃）时有效。低温段风扇压根不转、
高温段一直满转，两种情况都没有锯齿——工具会明说「测不出」，**不假装正常**。
若温度冲到 ≥85℃ 却一个锯齿都没有，判决会反过来提示你摸出风口查风扇。

## 4. 撞墙（节流）是坏了吗？
不是。节流是 CPU 的自我保护：温度到 100℃ 左右自动降频，宁可慢也不烧坏。
频繁出现只说明「散热规格不够本次负载」，对应建议是清灰/垫高/限功率。

## 5. 热阻 R_th 多少算好？
经验阈值（主流薄本标定）：

| R_th (℃/W) | 评价 |
|---|---|
| < 1.0 | 优秀 |
| 1.0 ~ 1.4 | 正常 |
| 1.4 ~ 1.8 | 偏高（建议清灰+换硅脂） |
| ≥ 1.8 | 差 |

游戏本/台式机散热更强，这套阈值会偏严；样本越多会越准，欢迎提 PR 补机型数据。

## 6. 报告里的「23W」和「33W」是什么区别？
- **23W = 实测安全线**：所有没撞墙的阶段里最高的稳态功耗——「验证过能长期跑的功率」。
- **33W = 理论天花板**：由热阻/散热模型外推到 100℃ 温度墙对应的功率——「风扇全程狂转的极限」。
日常负载看前者，评估极限潜力看后者。

## 7. 拟合出的热容 C 为什么说「没有物理意义」？
C 和 h 在拟合中同向缩放（一起乘 2，模拟曲线不变），所以绝对值不可辨识。
**能信的只有比值 h_on/h_off（散热增益）和时间常数 τ**——报告里就是这么标注的。

## 8. 测出来的数字精度多少？
温度传感器本身 ±1~2℃ 误差；报告保留两位有效数字，不代表精确到 0.01℃。
空载稳态波动、两个独立实验是否一致，都写进报告作为可信度自检。

## 9. 恒载要跑多久？
每段 ≥120 秒（`--quick` 为 90 秒）。太短温度没到稳态，热阻会被低估。
工具取每段「最后 40%」做稳态窗口，就是为了滤掉爬坡段。

## 10. 只有自己的 CSV（别的工具导的）能分析吗？
能，`analyze` 不挑出处。只要表头含 `CPU温度℃` 和 `CPU功耗W` 两列即可；
有 `CPU负载%` 更好（撞墙判定和风扇模型都用得上），有转速列就走转速路。

## 11. 测试怎么跑？会不会把我的机器烤了？
`python tests/test_smoke.py` —— 纯数据层面的验证（合成数据 + 已有示例数据），
**不会碰你的硬件、不需要管理员**。
